# Msg-forwarder-Go (VK + MAX → Telegram / Bark)

Небольшой мост на чистом Go (только стандартная библиотека: свой WebSocket, свой MessagePack, свой LZ4) для OpenWRT / Xiaomi AX3000T.

- входящие личные сообщения **VK** (User Long Poll API) и **MAX** (WebSocket веб-версии) → Telegram `sendMessage` и/или **Bark** (`POST /push`, в том числе с шифрованием AES-128-CBC);
- встроенный **локальный веб-интерфейс** для настройки без правки JSON вручную;
- **прямое подключение к Bot API по умолчанию**, прокси (HTTP/SOCKS5) — только при необходимости и только для Telegram; VK, MAX и Bark всегда идут напрямую;
- автопереподключение, без истории на диске, без телеметрии, без токенов в логах.

## Важные предупреждения

1. **MAX — неофициальный протокол, восстановленный по сторонним реализациям.** Использование веб-токена может нарушать условия сервиса. Риск блокировки аккаунта — на вас.
2. С 19.11.2026 веб использует бинарный протокол `ver=10` (`10`-байтный заголовок + MessagePack, опционально LZ4) на `wss://api.oneme.ru/websocket`. Старый JSON `ver=11` больше не отвечает.
3. Имитация браузера — только HTTP-заголовками (`Origin`, `User-Agent`) и ALPN `http/1.1`. **TLS-отпечаток остаётся Go-шным**; без внешней TLS-библиотеки (uTLS) это не исправить. Если WAF MAX начнёт блокировать подключения — потребуется отказаться от «только stdlib».
4. Веб-токен MAX временный. После истечения его нужно получить заново. Авто-логин по SMS в интерфейсе — **экспериментальный** режим: опкоды авторизации MAX не задокументированы и могут измениться. Надёжнее вручную скопировать токен из браузера.
5. Цель `<15 МБ ОЗУ` достигается лимитами кадров/кэша и жёстким лимитом кучи; реальный RSS теперь виден в каждой строке лога как `rss=NkB` (и в `ps -o pid,rss,cmd | grep Msg-forwarder-Go`).
6. Адрес прослушивания, отличный от локального (`127.0.0.1` или `::1`), открывает панель и редактор JSON в сети: используйте туннель или закрывайте доступ файрволом.
7. Свой сервер Bark или MAX получает токены и текст сообщений. Указывайте только доверенный адрес, даже если он находится в локальной сети.
8. MAX передаёт User-Agent, версию клиента, локаль, разрешение экрана и часовой пояс как данные устройства — это часть профиля, а не только заголовки запроса.
9. Токен встроенного интерфейса больше не рекомендуется передавать в адресной строке: адрес остаётся в истории браузера и может отразиться в логах.

## Быстрый старт (с веб-интерфейсом)

Программа стартует даже с пустым конфигом — неактивные сервисы просто отключаются, а интерфейс остаётся доступным:

```sh
# пользователь, от которого работает procd-сервис
addgroup Msg-forwarder-Go 2>/dev/null
adduser -S -H -G Msg-forwarder-Go Msg-forwarder-Go 2>/dev/null

mkdir -p /etc/Msg-forwarder-Go
chown Msg-forwarder-Go:Msg-forwarder-Go /etc/Msg-forwarder-Go
chmod 700 /etc/Msg-forwarder-Go
echo '{}' > /etc/Msg-forwarder-Go/config.json
chown Msg-forwarder-Go:Msg-forwarder-Go /etc/Msg-forwarder-Go/config.json
chmod 600 /etc/Msg-forwarder-Go/config.json
/etc/init.d/Msg-forwarder-Go start
```

Если пользователь `Msg-forwarder-Go` не создан, уберите строки `user`/`group` из `init.d-Msg-forwarder-Go` — иначе сервис не сможет записать `config.json` и `ui.token`.

Получить токен доступа к интерфейсу (только на самом роутере):

```sh
/usr/bin/Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ui-token
```

С рабочего компьютера откройте туннель:

```sh
ssh -L 8080:127.0.0.1:8080 root@192.168.1.1
# в браузере: http://127.0.0.1:8080/
```

Не передавайте токен в адресной строке: URL попадает в историю браузера, буфер обмена и может отразиться в логах. Если ссылка с токеном всё же была использована, считайте её одноразовой: после входа на главную страницу (`GET /?token=...`) сервер заменяет токен, старый URL больше не работает, а новый можно получить локально командой выше. Токен в URL принимается **только** на `GET /`; `/status`, `/control`, `/save` и другие адреса требуют куку или заголовок `Authorization: Bearer`, поэтому утечка ссылки не даёт прямого доступа к управлению.

Дальше токен сохраняется в `HttpOnly`-куке. Интерфейс слушает **только локальный адрес** по умолчанию (`127.0.0.1:8080`), не имеет CORS и отклоняет POST с чужого `Origin`. Если заменить адрес на нелокальный, панель и редактор JSON окажутся доступны в сети.

## Вкладка в LuCI

Если на роутере уже стоит LuCI, можно не открывать отдельный интерфейс вообще: вкладка появляется в меню **Службы → Msg-forwarder-Go** и работает с тем же самым конфигом.

Установка (файлы лежат в каталоге `luci/`):

```sh
scp luci/controller/Msg-forwarder-Go.lua root@192.168.1.1:/usr/lib/lua/luci/controller/
ssh root@192.168.1.1 'mkdir -p /usr/lib/lua/luci/view/Msg-forwarder-Go'
scp luci/view/Msg-forwarder-Go/index.htm root@192.168.1.1:/usr/lib/lua/luci/view/Msg-forwarder-Go/
ssh root@192.168.1.1 '/etc/init.d/uhttpd restart'
```

Вкладка умеет сохранять все поля, показывает «установлен/не задан» вместо значений в секретных полях, чекбоксы защиты секретов, кнопки проверки и команду получения токена встроенного интерфейса. Редактор JSON внизу вкладки показывает конфиг как есть: там токены и ключи видны открыто, поэтому не открывайте страницу посторонним. После сохранения автоматически выполняется `/etc/init.d/Msg-forwarder-Go restart`.

Если пункт меню не появился — доставьте совместимость с Lua-контроллерами:

```sh
opkg update && opkg install luci-compat   # или apk add luci-compat
```

На Lua-контроллерах в OpenWrt 24.10 всё ещё работает через `luci-compat`; в будущих версиях LuCI Lua объявлен устаревшим — тогда понадобится JS-вариант. Чтобы сэкономить ОЗУ, отключите встроенный интерфейс галочкой в LuCI (`ui_enabled = false`) — вкладка LuCI от этого не страдает.

## Что можно сделать в интерфейсе

| Раздел | Возможности |
|---|---|
| **VK** | Поле пользовательского токена; `vk_app_id` + кнопка-ссылка на OAuth ВКонтакте (`scope=messages`), проверка «Проверить VK» |
| **Telegram** | Bot token, chat ID, необязательный прокси, кнопки «Проверить доступ к Bot API» (без токена) и «Проверить Telegram» (`getMe`) |
| **MAX** | Access token, deviceId, WS URL, User-Agent, appVersion, опкод входящих; «Проверить MAX» (LOGIN); экспериментальная SMS-авторизация |
| **Bark** | Сервер, device key, пароль/ключ шифрования, заголовок, звук, группа, уровень, иконка, ссылка; «Проверить Bark» (реальная отправка push) |
| **Веб-интерфейс** | Адрес прослушивания и включение/отключение UI |
| **Действия** | Сохранить, Проверить…, Перезапустить сервис (procd поднимет его снова) |

Секретные поля (токены) при сохранении **не перезаписываются**, если не отмечен чекбокс «применить новое значение» — можно менять прокси/настройки, не вставляя токены заново. Файл конфига перезаписывается атомарно: временный файл получает права `0600` до замены итогового, имя временного файла включает идентификатор процесса.

Отдельный редактор JSON показывает секреты открыто — это нормально для локальной страницы, но опасно при нелокальном прослушивании. Формы показывают только «установлен/не задан», редактор — реальные значения.

## Панель управления соединениями

В обоих интерфейсах (LuCI и встроенном) для **VK / MAX / Telegram / Bark** есть отдельная строка:

- кружок: **зелёный** — работает, **серый** — выключено, **красный** — ошибка (рядом короткая причина);
- кнопки **Включить / Выключить / Перезапуск** — меняют состояние только в работающем процессе;
- кнопка **Автозапуск** — переключает флаг `autostart_vk` / `autostart_max` / `autostart_tg` / `autostart_bark` и сохраняет его в конфиг; именно он решает, запускать службу при старте роутера (по умолчанию включён для всех четырёх);
- **Пинг** — дешёвая проверка TCP-доступности хоста (5 с), **Тест** — настоящая проверка токена/LOGIN/push (`-test vk|tg|max|bark`), а `-test api` — проверка доступности Bot API без токена (DNS → TCP → TLS → HTTPS 401);
- для Telegram дополнительно **Узнать chat_id**; для Telegram и Bark — поле **Тестовое сообщение** с кнопками **Отправить в Telegram** / **Отправить в Bark**.

Важно: **встроенный HTTP-сервер управления всегда включён** на `ui_listen` (по умолчанию `127.0.0.1:8080`), даже если отключить саму HTML-страницу через `ui_enabled=false`. LuCI обращается к нему через встроенный клиент `Msg-forwarder-Go -ctl ...` (токен берётся из `/etc/Msg-forwarder-Go/ui.token`, `curl` на роутере не нужен). Не отключайте этот сервер, пока пользуетесь вкладкой LuCI.

## Отладочный лог

В обеих панелях (встроенной и LuCI) есть раздел **«Отладочный лог»**: кружок статуса, кнопки **Включить / Выключить / Статус** и ссылка **Скачать лог**. Включение сохраняется: рядом с конфигом создаётся файл-метка `debug.enabled`, поэтому после перезапуска процесса (и перезагрузки роутера) отладка поднимается автоматически и ловит ошибки старта. Кнопка «Выключить» удаляет метку. Файл лога остаётся на диске и скачивается и после выключения.

Файл лежит рядом с конфигом — `/etc/Msg-forwarder-Go/debug.log` (права 0600), предыдущая ротация — `debug.log.1`. Лимит **1 МБ + 1 МБ**: при превышении текущий файл становится предыдущим, а новый начинается с нуля. Этого достаточно, чтобы поймать редкие сбои в релизе: история соединений, переподключений и ошибок за несколько дней, а flash не заполняется. По умолчанию файл не ведётся — отладка включается только по кнопке.

Чтобы не писать во flash каждой строкой, записи копятся в ОЗУ (до 64 КБ) и сбрасываются на диск **раз в 10 минут**. Досрочный сброс происходит при заполнении буфера, перед скачиванием, при выключении и при завершении процесса. Каждый внеочередной сброс оставляет в логе строку `[DEBUG] буфер полон: N байт, внеочередной сброс №M`, а счётчик `forced_flushes` виден в статусе панели — по нему можно решить, нужно ли увеличить буфер. Потеря последних десяти минут при краше — осознанная плата за минимальный износ flash.

В файл попадают:

- заголовок сессии: PID, версия сборки (с хешем коммита, если известен), ID сессии, снимок безопасных настроек — `incoming_opcode`, схема/хост прокси, хосты MAX/Bark, флаги автозапуска и адрес панели;
- все обычные диагностические сообщения (`stderr` дублируется в файл, когда отладка включена);
- трафик: тип события, размеры кадров и текста, opcode/seq, **список ключей msgpack** (без значений), статусы HTTP-ответов, длительности запросов, количество событий и кадров, попадания в кэш и дедупликацию;
- сквозной `trace=N`: один и тот же номер у входящего события и у постановки в очередь Telegram/Bark и у результата отправки — события можно связать между горутинами; каждая строка дополнительно имеет монотонный номер `#N` и `rss=NkB` — потребление ОЗУ процессом на момент добавления строки (на Linux из `/proc/self/status`, на других системах из метрик Go);
- соединения: этапы WebSocket-handshake и SOCKS5, INIT/LOGIN/подписки MAX, long poll VK, включение/выключение служб;
- сбои: **текст ошибки** (TLS/DNS/протокольные причины вместо `%T`), коды API, таймауты ожидания ack, счётчики повторов и отброшенных строк. Ошибки `net/http`, содержащие URL с токеном, по-прежнему сводятся к типу.

**Не пишутся** токены, пароли, имена контактов и текст сообщений. Дополнительно каждая строка проверяется на совпадение с секретами из конфига (токены, ключи, device ID, логин/пароль прокси) — совпадения заменяются на `***`. Идентификаторы контактов и чатов усекаются до последних четырёх символов.

То же самое доступно из CLI (используется вкладкой LuCI):

```sh
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl debug -action status
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl debug -action on
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl debug -action off
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl debug -action log
```

Скачивание защищено той же авторизацией, что и остальная панель: кука или `Authorization: Bearer` для встроенного интерфейса, CSRF-токен LuCI для кнопок. При скачивании отдаются предыдущий и текущий файлы одной последовательностью.

### Какой бот прописан и где его взять

**Никакой бот не «прописан» в коде** — это ваш собственный бот. Порядок:

1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя и username → получить токен вида `123456789:AA...`.
2. Вставить этот токен в поле **Bot token** (в LuCI или встроенном интерфейсе), поставить галочку «применить новое значение», сохранить.
3. Написать боту любое сообщение (иначе Telegram не отдаст chat_id).
4. Нажать **Узнать chat_id** — результат появится в поле статуса и автоматически подставится в поле **Chat ID** (если не подставилось — скопируйте вручную).
5. Нажать **Проверить доступ к Bot API**: если приходит `401` — прямой доступ есть, прокси оставляйте пустым. Затем **Сохранить и перезапустить**, **Тест** и **Отправить тест**. Прокси нужен только если эта проверка не проходит.

Чат может быть личным с ботом, группой или каналом — main `chat_id` задаёт только получателя. Исходящие сообщения от вас программа не пересылает: она отправляет в Telegram только входящие личные сообщения VK/MAX.

### Проверка доступа к Bot API

Перед настройкой прокси проверьте, нужен ли он вообще. Проверка не требует токена: запрос идёт на `api.telegram.org/bot0:0/getMe`, а признаком успеха служит ответ `401 Unauthorized`.

С роутера:

```sh
curl -sS -m 10 'https://api.telegram.org/bot0:0/getMe'
# или, если curl не установлен:
uclient-fetch -q -O - 'https://api.telegram.org/bot0:0/getMe'
```

Ожидаемый ответ:

```json
{"ok":false,"error_code":401,"description":"Unauthorized: invalid token specified"}
```

В самой программе то же самое делает команда без токена:

```sh
/usr/bin/Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -test api
```

и кнопка **«Проверить доступ к Bot API»** в обоих интерфейсах. Если проверка проходит, поле прокси оставляйте пустым.

## Прокси Telegram

Поддерживаются `http://`, `https://`, `socks5://`, `socks5h://`, в том числе с логином/паролем в URL. Пример для локального прокси на роутере: `socks5://127.0.0.1:1080`. Для SOCKS5 лучше указывать `socks5h://`: в этом случае DNS-запросы тоже идут через прокси и не уходят локальному резолверу.

**MTProto-прокси (mtg/MTProxy) и TG WS Proxy здесь не подходят.** Они туннелируют только MTProto-трафик клиента Telegram к дата-центрам, а программа ходит в Bot API по обычному HTTPS. Telegram официально не поддерживает MTProxy для Bot API. Если прямой доступ к `api.telegram.org` заблокирован, нужен общий HTTP/SOCKS5-прокси или VPN, либо DPI-обход (Zapret) — но не MTProto.

Прокси применяется **только** к `api.telegram.org`. VK, MAX и Bark не используют ни системный, ни переменные окружения `HTTP_PROXY`/`HTTPS_PROXY` — это специально, чтобы трафик мессенджеров и push-уведомлений не уходил через сторонний узел.

### Можно ли просто ввести логин и пароль?

**Нет, ни для VK, ни для MAX это не работает** — и дело не в лени разработчика:

- **VK** давно не разрешает вход по логину/паролю через API. Нужен именно OAuth-токен пользователя с правом `messages`. Старый «парольный» способ убран, а попытка автоматизировать веб-вход быстро упрается в капчу и двухфакторную защиту. Поэтому в интерфейсе есть ссылка на OAuth: вы логинитесь **в браузере ВКонтакте**, а программа получает только готовый токен. Пароль нигде не вводится и не хранится.
- **MAX** не имеет пароля как такового: веб-вход — это **номер телефона + код из SMS** (иногда ещё капча). То есть «как на новое устройство через SMS» — да, именно так и работает экспериментальный сценарий в интерфейсе: генерируется новый `deviceId`, запрашивается код, вводится код, получается access token.
- **Telegram** — только bot token от `@BotFather`; логин/пароль не используются вообще.

### Авторизация в MAX через SMS — насколько безопасно?

С точки зрения **утечки данных** — нормально: токен и deviceId остаются в конфиге с правами `0600`, SMS-код никуда не логируется. Но есть риски другого плана:

1. Это **неофициальный протокол**. Опкоды `17`/`18`/`224` восстановлены из сторонних репозиториев; после обновления веб-клиента MAX они могут измениться — тогда авторизация просто перестанет работать.
2. MAX может расценить вход с нового устройства/небраузерного TLS-отпечатка как подозрительный и удержать аккаунт или потребовать дополнительную проверку.
3. SMS-код уязвим для перехвата/SIM-swap — как и любой вход по SMS.

**Поэтому рекомендую:** один раз зайти в `web.max.ru` в обычном браузере, скопировать уже выданный токен и deviceId и вставить их в поле. Это данные реальной браузерной сессии — программа не «логинится», а только подключается к WebSocket с готовым токеном. SMS-кнопки оставил как запасной путь, если токен истёк и браузер недоступен.

Кнопки «Проверить VK / Telegram / MAX / Bark» печатают короткий результат без токенов. Встроенный интерфейс выполняет проверки внутри процесса, вкладка LuCI вызывает скрытые режимы бинарника (`Msg-forwarder-Go -test vk|tg|max|bark`); для проверки Bot API токен не нужен. Все проверки читают уже сохранённый конфиг: после изменения токена, прокси или адресов сначала нажмите «Сохранить и перезапустить».

Кнопки панели соединений в LuCI работают через встроенный клиент того же бинарника:

```sh
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl status
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl control -service vk -action on
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl control -service tg -action autostart -value false
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl send -service tg -text 'проверка'
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -ctl send -service bark -text 'проверка'
Msg-forwarder-Go -config /etc/Msg-forwarder-Go/config.json -test bark
```

## Получение токенов вручную

### MAX

1. Войдите в <https://web.max.ru> в обычном браузере.
2. F12 → Console:
   ```js
   JSON.parse(localStorage.__oneme_auth).token
   localStorage.__oneme_device_id
   ```
3. Вставьте значения в поля интерфейса (или в конфиг).

Помимо токена и deviceId, MAX получает данные устройства: User-Agent, версию клиента, локаль, разрешение экрана и часовой пояс. Это часть профиля подключения, а не только декоративные заголовки. Свой WebSocket-сервер MAX, если он используется, видит токен и текст сообщений — доверяйте только ему.

### VK

Нужен **пользовательский** токен с правом `messages` (не токен сообщества). Укажите `vk_app_id`, нажмите ссылку OAuth в интерфейсе, разрешите доступ и скопируйте токен из адресной строки.

### Telegram

Токен от `@BotFather`, chat ID — кнопкой **Узнать chat_id** в интерфейсе (или, например, от `@userinfobot`).

### Bark

1. Установите приложение Bark на iPhone и откройте его.
2. Скопируйте **device key** из тестового URL/настроек — это поле «куда отправлять».
3. Для публичного сервера оставьте `https://api.day.app`; для своего сервера укажите, например, `http://192.168.1.10:8080`. Свой сервер Bark получает device key, ключ шифрования и текст сообщений — используйте только доверенный адрес.
4. Если нужна сквозная шифровка: в Bark откройте **Push Encryption**, выберите `AES-128-CBC` и задайте KEY **ровно из 16 символов**. Такой же ключ введите в поле «Пароль/ключ шифрования» и включите галочку шифрования.
5. Нажмите **Проверить Bark** — программа отправит настоящее тестовое push-уведомление.

При шифровании в `ciphertext` уходит JSON с `title`, `subtitle`, `body`, `sound`, `group`, `level`, `icon`, `url`; IV генерируется случайно для каждого сообщения и передаётся в параметре `iv`. Bark-сервер и APNs видят только шифртекст.

## Конфиг

`/etc/Msg-forwarder-Go/config.json` (полный пример — `config.example.json`):

```json
{
  "vk_token": "",
  "vk_app_id": "1234567",
  "vk_api_version": "5.131",
  "tg_bot_token": "",
  "tg_chat_id": 123456789,
  "telegram_proxy": "",
  "max_token": "",
  "max_device_id": "",
  "max_ws_url": "wss://api.oneme.ru/websocket",
  "max_user_agent": "Mozilla/5.0 ...",
  "max_app_version": "26.11.9",
  "incoming_opcode": 128,
  "bark_server_url": "https://api.day.app",
  "bark_device_key": "",
  "bark_key": "",
  "bark_encrypt": false,
  "bark_title": "Msg-forwarder-Go",
  "bark_sound": "birdsong",
  "bark_group": "Msg-forwarder-Go",
  "bark_level": "active",
  "bark_icon": "",
  "bark_click_url": "",
  "autostart_vk": true,
  "autostart_max": true,
  "autostart_tg": true,
  "autostart_bark": true,
  "ui_enabled": true,
  "ui_listen": "127.0.0.1:8080"
}
```

`max_ws_url` с открытым `ws://` разрешён только для `localhost`: при LOGIN MAX передаёт токен, и по незашифрованному каналу его перехватил бы любой наблюдатель. Для внешнего сервера используйте `wss://`.

Полный пример в `config.example.json` содержит служебное поле `_warning` с короткими предупреждениями. Программа игнорирует его, редактор JSON сохраняет как обычное неизвестное поле; удалять его не обязательно.

`incoming_opcode=128` — компромисс: в разных источниках 128 называют то новым сообщением, то редактированием. Если сообщения не приходят — попробуйте другое значение и включите отладку по логам ошибок разбора (текст сообщений всё равно не логируется).

## Сборка под Xiaomi AX3000T

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 \
  go build -trimpath -ldflags="-s -w -buildid=" -o Msg-forwarder-Go .
```

Проверьте архитектуру: `uname -m` → `aarch64`. Готовый бинарник рассчитан только на arm64; сборки для 32-битного ARM (armv7) нет.

```sh
scp Msg-forwarder-Go root@192.168.1.1:/usr/bin/Msg-forwarder-Go
scp init.d-Msg-forwarder-Go root@192.168.1.1:/etc/init.d/Msg-forwarder-Go
ssh root@192.168.1.1 '
  chmod 755 /usr/bin/Msg-forwarder-Go /etc/init.d/Msg-forwarder-Go
  /etc/init.d/Msg-forwarder-Go enable
  /etc/init.d/Msg-forwarder-Go start
'
```

Для `procd`-скрипта нужен пользователь `Msg-forwarder-Go` (создайте его или уберите строки `user`/`group`).

## Логи

`stderr` → syslog OpenWRT. Только:

- состояние подключений и адрес прослушивания UI;
- тип сетевой ошибки (`timeout`, `network error`, тип ошибки), коды API;
- предупреждение о слишком вольных правах конфига.

Каждая строка, и в syslog, и в отладочном файле, содержит `rss=NkB` — текущее потребление ОЗУ процессом на момент записи. Так можно следить за ростом памяти без `ps` на роутере.

Токены, имена контактов и текст сообщений **никогда** не логируются самой программой. Токен UI тоже не пишется в лог — только команда, как его получить. Исключение может создать только сам пользователь, если передаст токен в адресной строке: поэтому так делать не рекомендуется.

Когда отладка включена кнопкой в панели, те же сообщения дублируются в `/etc/Msg-forwarder-Go/debug.log` и дополняются метаданными трафика — подробности в разделе «Отладочный лог». Файл ограничен лимитом 1 МБ плюс 1 МБ ротации и скачивается из панели.

Строки от серверов (например, поле `error` от MAX) маскируются по секретам из конфига **до** записи и в syslog, и в панели — подменённый сервер не сможет вернуть токен в тексте ошибки. Редиректы HTTP-клиентов ограничены тем же хостом и портом: `302` на внутренний адрес не пройдёт. Тяжёлые проверки и скачивание лога ограничены двумя одновременными операциями.

## Чего программа не делает

- не пишет историю/состояние на диск (кроме конфига, его резервной копии `config.json.bak` с правами 0600, `ui.token` и отладочного лога, если его включить вручную);
- не использует базу данных и не хранит пароли;
- не отправляет аналитику, метрики и crash-отчёты;
- не использует `http.ProxyFromEnvironment` (прокс только для Telegram, и только из конфига);
- не логирует токены и содержимое сообщений.
